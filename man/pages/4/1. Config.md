When you launch `dices`, it reads a handful of settings to decide where to keep
your history, whether to greet you with a banner, how strict must the sandbox
be, and so on. All of these are loaded from a cascading configuration sources
list.

## Where `dices` looks for configurations

`dices` checks out the files inside the *project directory*, whose location
follows the conventions of your operating system. It is built from the
application name `dices` (and, on macOS, the bundle id
`site.zannabianca1997.dices.dices`):

- **Linux.** Config is at `$XDG_CONFIG_HOME/dices` (defaults to
  `~/.config/dices`).
- **macOS.** Config directory lives under `~/Library/Application
  Support/site.zannabianca1997.dices.dices`.
- **Windows.** Config is at `%APPDATA%\dices\config`.

Inside the project directory `dices` search for:
- `Config.toml`: global configuration file.
- `themes/`: custom themes
- `banners/`: custom opening and closing banners

If `dices` cannot determine a home directory the REPL keeps working with
built-in defaults.

## Resolution order

Settings are merged in order, with each one overriding the previous. From lowest
to highest priority:

1. **Built-in defaults.**.
2. **`Config.toml`** in the project config directory, if it exists. 
3. **`Dices.toml`** in the current directory or any of its parents.
4. **Custom configuration file given with `--config`.**
5. **Environment variables** 
6. **Command-line flags.**

Env variables are prefixed with `DICES_`. The prefix is stripped and the
remaining name is split on `_` into nested keys, so `DICES_SKIN_THEME` sets
`skin.theme`, `DICES_HISTORY_CAPACITY` sets `history.capacity`, and
`DICES_STD_FILESYSTEM` sets `std.filesystem`.

Pass `--no-default-config` to skip steps 2 and 3 entirely, and start straight
from the built-in defaults, making the configuration depending only from the
environment.

## Configuration cheat sheet

Here are the sections of the configuration

### `[history]`

Controls the command history of the REPL.

- **`file`**: path to the history file. Defaults to `history.txt` in the data
  directory. A relative path is resolved against the directory of the config
  file that declares it; an absolute path is used as-is. Set it to null keeps
  history in memory only.
- **`capacity`**: how many past commands are kept. Default is `1000`.

### `[skin]`

Controls terminal coloring.

- **`banners`**: whether to show the opening and closing banners. Default is
  `true`, except if `-C` is provided.
- **`graphical`**: whether to use non-ASCII characters. Default is `true` when
  the output is a terminal, `false` otherwise.
- **`color`**: whether to colorize the output. Default is `true` when the output
  is a terminal, `false` otherwise.
- **`theme`**: the name of the theme to use.

See _4.2. Theming_ for how to add or customize themes.

### `[std]`

Options for the standard library.

- **`filesystem`**: grant the repl access to the filesystem. Default is `true`.

## A complete example

```toml
# ~/.config/dices/Config.toml

[history]
file = "/my/custom/history.txt"
capacity = 5000

[skin]
banners = true
graphical = true
color = true
theme = "CatppuccinMocha"

[std]
filesystem = true
```
